
# Session Handoff: Bronze/Silver Simplification — 1 Function per Table

**Date:** 2026-09-23 (session 2)
**Branch:** `23092026_hung_debug_prefect_and_config`
**Scope:** Simplify và independent hóa bronze/silver flow. Mỗi table 1 hàm riêng. Silver dùng Spark SQL từ `.sql` files.

---

## 1. Kiến trúc mới sau session này

```
CSV nguồn
  └─► bronze_flow.py  (load_<table> per file)
        └─► MinIO Bronze (Delta format, partition _load_date)
              └─► silver_flow.py  (build_<table> per target)
                    └─► spark.sql(sql/staging/<table>.sql)
                          └─► PostgreSQL schema stg
```

---

## 2. bronze_flow.py — pattern mới

**Nguyên tắc:**
- 1 hàm `load_<table>()` per source file
- Hàm nhận `(spark, config, stack, load_date)` — không tự tạo session
- `@flow` tạo Spark 1 lần → gọi lần lượt các loader trong `_LOADERS` list
- Khi debug: log `bronze_load_started table=<name>` chỉ rõ hàm nào stuck

**Shared helpers:**
- `_load_csv()` — read CSV với Bronze options
- `_write_bronze()` — gọi `add_bronze_metadata()` + `write_delta_partitioned()` từ `delta_utils`

**Source tables mapped:**
```
load_application           → application.csv
load_bureau                → bureau.csv
load_bureau_balance        → bureau_balance.csv
load_previous_application  → previous_application.csv
load_installments_payments → installments_payments.csv
load_pos_cash_balance      → POS_CASH_balance.csv
load_credit_card_balance   → credit_card_balance.csv
```

---

## 3. silver_flow.py — pattern mới

**Nguyên tắc:**
- 1 hàm `build_<table>()` per target bảng
- Mỗi hàm: `_register_bronze_view()` → `spark.sql(sql_file)` → `write_jdbc()`
- SQL transformation logic nằm trong `cli/flows/sql/staging/<table>.sql`
- Thứ tự build: **Dims trước → Facts sau** (FK integrity)

**Helper `_register_bronze_view(spark, stack, table)`:**
- Đọc Delta từ MinIO path `s3a://<bucket>/bronze/<table>`
- Register temp view `bronze_<table>` trong Spark session

**SQL files path:** `cli/flows/sql/staging/` — resolved bằng `Path(__file__).resolve().parents[2] / "sql" / "staging"`

**Build order:**
```
Dim_Date (generated, không cần Bronze)
Dim_Application_Status  → bronze_previous_application
Dim_Contract_Type       → bronze_application
Dim_Customer            → bronze_application
Fact_Loan_Repayment     → bronze_installments_payments + bronze_previous_application
Fact_Loan_Application   → bronze_application + bronze_previous_application
Fact_Bureau_Credit      → bronze_bureau
Fact_Bureau_Monthly_Snapshot → bronze_bureau_balance
Fact_Credit_Balance     → bronze_credit_card_balance
Fact_POS_CASH_balance   → bronze_pos_cash_balance
```

## 4. SQL files — từ DDL → SELECT transformation

Tất cả 10 file trong `cli/flows/sql/staging/` đã được viết lại từ DDL (CREATE TABLE) sang SELECT queries:

| File | Temp views input | Notes |
|---|---|---|
| `dim_date.sql` | `date_range` | Generated by build_dim_date() |
| `dim_application_status.sql` | `bronze_previous_application` | DISTINCT + DENSE_RANK |
| `dim_contract_type.sql` | `bronze_application` | DISTINCT + DENSE_RANK |
| `dim_customer.sql` | `bronze_application` | SCD2 initial load, Is_Current_Flag='Y' |
| `fact_loan_repayment.sql` | `bronze_installments_payments`, `bronze_previous_application` | LEFT JOIN on SK_ID_PREV |
| `fact_loan_application.sql` | `bronze_application`, `bronze_previous_application` | LEFT JOIN on SK_ID_CURR |
| `fact_bureau_credit.sql` | `bronze_bureau` | hash(SK_ID_BUREAU) SK |
| `fact_bureau_monthly_snapshot.sql` | `bronze_bureau_balance` | MONTHS_BALANCE → last_day |
| `fact_credit_balance.sql` | `bronze_credit_card_balance` | MONTHS_BALANCE → last_day |
| `fact_pos_cash_balance.sql` | `bronze_pos_cash_balance` | MONTHS_BALANCE → last_day |

## 5. Known limitations (cần xử lý tiếp)

1. **FK surrogate key lookup chưa implement:**
   - `Fact_Loan_Application.Contract_Type_SK`, `Status_SK` đang là placeholder `-1`
   - Cần JOIN vào Dim tables sau khi write để resolve SK thật
   - Pattern đúng: build dim → write PostgreSQL → đọc lại dim từ PostgreSQL → join với fact

2. **SCD Type 2 cho Dim_Customer:**
   - Hiện tại full refresh (overwrite), Is_Current_Flag luôn 'Y'
   - Cần implement MERGE logic khi có incremental load

3. **Bronze Delta migration:**
   - Nếu có Bronze data cũ dạng Parquet, `spark.read.format("delta")` sẽ fail
   - Cần rerun Bronze flow trước Silver

4. **`_SQL_DIR` trong silver_flow.py:**
   - Dùng `Path(__file__).resolve().parents[2]` — đây là path tới `cli/flows`, OK vì file nằm ở `cli/flows/serving/`
   - `parents[0]` = `serving/`, `parents[1]` = `flows/serving` ... wait: `parents[2]` = `cli/flows` ✅
